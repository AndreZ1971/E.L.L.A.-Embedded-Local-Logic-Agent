Deployment & Privilege Architecture

E.L.L.A. operates directly above the Android framework layer, designed for OEM factory pre-installation.

Privileged System App /system/priv-app

Core capabilities — CallScreeningService, NotificationListener, Accessibility, Write-Secure-Settings — are granted directly via OEM platform permissions (privapp-permissions.xml), eliminating all end-user configuration hurdles.

Enterprise DPC Engine

Deterministic app control and situational mode enforcement (EllaDeviceOwnerPlugin.kt) via DevicePolicyManager.setPackagesSuspended() for distraction-free Driving and Focus modes.

Hardware Evaluation Target

Standalone evaluation on unprovisioned zero-account devices:

adb shell dpm set-device-owner com.ella.phone/.EllaDeviceAdminReceiver

Deterministic Tool Calling & Execution Pipeline

Running function calling entirely on-device via a 3 B parameter model requires robust architectural guardrails rather than naive prompt trust:

Optimized Base Model

Standardized on Qwen 2.5 3B (ChatML), benchmarked specifically for high parameter fidelity across native intents.

Brace-Depth Parser

Robust string- and escape-safe AST extraction (extractToolCall()) prevents malformed JSON execution failures.

Directive Policy Layer

Client-side rule evaluation enforces an unchangeable Default-Deny policy before dispatching calls to native Android interfaces or SQLite tables.

Explicit Confirmation Gateway

Tools with irreversible real-world effects — make_call, send_sms, reply_to_message, forget — require an explicit one-tap Confirmation Card. Accidental executions are architecturally eliminated.

Autonomous Cloud Fallback (optional)

If the SLM encounters structural stalling during intent resolution, the pipeline can escalate that single query to a configured cloud endpoint — visibly tagged for the user.

Hallo — ich bin E.L.L.A.

E.L.L.A. steht für Embedded Local Logic Agent — deine persönliche KI-Assistentin auf dem Smartphone. Ich filtere Anrufe, schreibe Nachrichten, kenne deinen Kalender, stelle Wecker, erinnere dich an Dinge und passe mein Verhalten an die Situation an, in der du gerade bist — im Auto, im Meeting, nachts, auf Reisen.

Das Besondere: Ich laufe direkt auf deinem Gerät. Deine Gespräche, deine Kontakte, deine Daten bleiben auf deinem Telefon, solange du nichts anderes ausdrücklich erlaubst.

Wie ELLA grundsätzlich funktioniert

On-device zuerst. ELLA hat ein eigenes, kleines Sprachmodell (standardmäßig Qwen 2.5 3B, über die quelloffene llama.cpp-Engine) direkt auf deinem Gerät. Wenn du etwas sagst oder schreibst, versucht ELLA zuerst komplett offline zu antworten — kein Internet, kein Server.

Cloud nur als Ausweichmöglichkeit, nie heimlich. Wenn du einen Cloud-API-Key hinterlegt hast, kann ELLA automatisch ausweichen — immer sichtbar gekennzeichnet (z. B. (OpenAI) am Ende der Antwort).

Werkzeuge (Tools). Wenn du ELLA bittest, etwas zu tun, entscheidet das Sprachmodell, welches der 66 Werkzeuge passt, und ELLA führt es aus — entweder direkt auf dem Gerät (SQLite) oder über eine native Android-Schnittstelle.

Erste Schritte

Installation

E.L.L.A. Phone ist aktuell nicht im Play Store verfügbar. APK-Datei übertragen (USB oder Download) → "Installation aus unbekannten Quellen" erlauben → installieren → App öffnen.

Schritt 1 — Die vier Grundsätze

Beim allerersten Start siehst du einen Bildschirm "Bevor wir anfangen." mit den vier Dingen, die ELLA niemals tun wird. Am Ende ein einziger Button: "Ich habe das verstanden." Nicht überspringbar.

Schritt 2 — Einrichtung

Begrüßung → Name (optional) → Geräte-Scan → Stimme wählen → Standort (optional) → Fertig. Alternativ: "Identität von einem anderen Gerät übertragen" (MicroSD, AES-256-GCM).

Schritt 3 — KI-Modell herunterladen

ELLA schlägt die passende Modellgröße für dein Gerät vor. Fortschrittsbalken, jederzeit abbrechbar.

Der Chat-Bildschirm

Mikrofon: Antippen → Ergebnis landet nur im Textfeld, wird nicht automatisch gesendet.

Freihand-Modus (Bluetooth-Kopfhörer): ELLA erkennt Kopfhörer und fragt per Banner. ELLA hört niemals automatisch mit — du startest den Modus explizit.

Sprachausgabe: 🔊/🔇 oben in der Werkzeugleiste. Pausieren: "Pausiere für 30 Minuten" → Countdown-Banner mit "Fortsetzen"-Button.

Bewertung: 👍/👎 unter jeder Antwort → ELLA fasst Feedback on-device zu einer Präferenz-Notiz zusammen.

Directive-Karte: Verstöße gegen die vier Grundsätze → rote Karte "⊘ E.L.L.A. DIRECTIVE" mit Erklärung. Nie stillschweigend.

Bestätigungskarten

Vier Werkzeuge fragen einmal nach, bevor sie wirklich ausgeführt werden: Anrufen, SMS senden, Nachricht beantworten, Vergessen. Orangefarbene Karte mit "Ja, ausführen" / "Abbrechen".

Meine vier Grundsätze (Directive)

Unveränderlich — keine Einstellung, kein Befehl kann sie außer Kraft setzen. SHA-256 + OpenTimestamps versiegelt.

# Grundsatz Was das bedeutet
I Kein Schaden Keine kostenpflichtigen Aktionen ohne Bestätigung. Kein Löschen ohne expliziten Befehl.
II Keine Täuschung Jede Werkzeug-Ausführung wird protokolliert. Cloud-Herkunft immer sichtbar.
III Keine Überwachung Mikrofon/Kamera nur auf expliziten Befehl. Kein Wake-Word. Standort nur IP-basiert, nie GPS, nie im Hintergrund.
IV Keine Weitergabe Keine Nutzerdaten an externe Server ohne explizite Zustimmung. Cloud-Fallback braucht eigenen API-Key.

Problemlösung

Problem Lösung
ELLA antwortet nicht / sehr langsam Auf schwächerer Hardware kann on-device mehrere Minuten dauern. Cloud-Key hinterlegen und "Offline-First" ausschalten beschleunigt.
Aktion behauptet, ausgeführt — nichts passiert Bekannte Grenze kleiner Sprachmodelle. Mit "…auflisten" gegenprüfen (z. B. "Zeig mir meine Wecker").
Werkzeug meldet Fehler Meist fehlende Android-Berechtigung (beim ersten Aufruf bestätigen) oder fehlender Cloud-Key bei Bild-Funktionen.
Google-Verbindung schlägt fehl Internetverbindung prüfen; ggf. in Einstellungen erneut verbinden.
Anruf-Filterung lässt sich nicht ausschalten Nicht per Sprachbefehl möglich. Android-Einstellungen → Standard-Apps → andere Anruf-Filter-App wählen.
