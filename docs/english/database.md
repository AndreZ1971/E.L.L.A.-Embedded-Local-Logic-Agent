## Connection

The API connects via a connection pool (`mysql2/promise`):

```typescript
// apps/api/src/config/database.ts
export const pool = mysql.createPool({
  host: env.dbHost,
  port: env.dbPort,
  database: env.dbName,
  user: env.dbUser,
  password: env.dbPassword,
  waitForConnections: true,
  connectionLimit: 10,
});
```

## Schema Migration

The schema is executed automatically on every API startup (`runMigrations()` in `apps/api/src/config/migrate.ts`). All statements use `IF NOT EXISTS` or `INSERT IGNORE` — fully idempotent. To apply manually:

```powershell
"E:\MariaDB\server\bin\mysql.exe" -u root -p ella < database/schema.sql
```

## Tables

### `sessions` — Conversation Sessions

```sql
CREATE TABLE IF NOT EXISTS sessions (
  id         VARCHAR(255) PRIMARY KEY,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

| Column       | Type         | Description                                  |
| ------------ | ------------ | -------------------------------------------- |
| `id`         | VARCHAR(255) | Session ID (UUID, generated by the frontend) |
| `updated_at` | DATETIME     | Last activity — updated automatically        |

### `session_messages` — Conversation History

```sql
CREATE TABLE IF NOT EXISTS session_messages (
  id         INT AUTO_INCREMENT PRIMARY KEY,
  session_id VARCHAR(255) NOT NULL,
  role       ENUM('user', 'assistant') NOT NULL,
  content    TEXT NOT NULL,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (session_id) REFERENCES sessions(id) ON DELETE CASCADE
);
```

| Column    | Type | Description                                                    |
| --------- | ---- | -------------------------------------------------------------- |
| `role`    | ENUM | Only `user` and `assistant` — `tool` messages are filtered out |
| `content` | TEXT | Message content in plain text                                  |

**Strategy:** On `sessionStore.set()` the session is fully deleted and re-written (DELETE + re-INSERT). Max. 40 messages per session. `tool` messages are filtered out — they are only valid during an active request.

### `memories` — Vector Memory

```sql
CREATE TABLE IF NOT EXISTS memories (
  id         INT NOT NULL AUTO_INCREMENT PRIMARY KEY,
  type       ENUM('user', 'system', 'note') NOT NULL,
  content    TEXT NOT NULL,
  embedding  MEDIUMTEXT NOT NULL,
  source     VARCHAR(255),
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX IF NOT EXISTS idx_memories_type ON memories (type);
```

| Column      | Type         | Description                                                                   |
| ----------- | ------------ | ----------------------------------------------------------------------------- |
| `type`      | ENUM         | `user` (facts about the user), `system` (tool usage), `note` (explicit notes) |
| `content`   | TEXT         | Original text of the memory                                                   |
| `embedding` | MEDIUMTEXT   | JSON array with 768 float values (nomic-embed-text)                           |
| `source`    | VARCHAR(255) | Where the memory came from (optional)                                         |

**Recall:** The last 500 entries are loaded, cosine similarity is computed in Node.js, everything below 0.3 is filtered out, top-5 are returned.

### `rules` — Allow/Deny Rules

```sql
CREATE TABLE IF NOT EXISTS rules (
  id         INT AUTO_INCREMENT PRIMARY KEY,
  name       VARCHAR(255) NOT NULL,
  tool_name  VARCHAR(100) NOT NULL DEFAULT '*',
  `trigger`  VARCHAR(255) NOT NULL DEFAULT 'always',
  action     ENUM('allow', 'deny') NOT NULL DEFAULT 'allow',
  enabled    BOOLEAN      NOT NULL DEFAULT TRUE,
  created_at DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

| Column          | Type         | Description                                           |
| --------------- | ------------ | ----------------------------------------------------- |
| `tool_name`     | VARCHAR(100) | `*` = applies to all tools, otherwise a specific name |
| `` `trigger` `` | VARCHAR(255) | `always` · `hour > 22` · `disk_c > 85`                |
| `action`        | ENUM         | `allow` or `deny` — deny always wins (SQL sort order) |
| `enabled`       | BOOLEAN      | Disable without deleting                              |

**Note:** `` `trigger` `` must be written with backticks — `trigger` is a reserved SQL keyword.

**Default rules (IDs 1–85):** Inserted via `INSERT IGNORE` on startup. `clean_temp` and `empty_recycle_bin` intentionally have no default rule — they must be explicitly enabled.

### `tool_executions` — Audit Log

```sql
CREATE TABLE IF NOT EXISTS tool_executions (
  id          INT AUTO_INCREMENT PRIMARY KEY,
  tool_name   VARCHAR(100) NOT NULL,
  args        JSON         NOT NULL,
  result      JSON,
  success     BOOLEAN      NOT NULL,
  error       TEXT,
  executed_at DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

| Column    | Type    | Description                                 |
| --------- | ------- | ------------------------------------------- |
| `args`    | JSON    | Parameters with which the tool was called   |
| `result`  | JSON    | Return value (`output` field of ToolResult) |
| `success` | BOOLEAN | Successful or error                         |
| `error`   | TEXT    | Error message when `success = false`        |

Every `toolExecutor.execute()` call writes an entry via `setImmediate` — fire-and-forget, does not block the response.

### `system_events` — Worker Event Log

```sql
CREATE TABLE IF NOT EXISTS system_events (
  id         INT AUTO_INCREMENT PRIMARY KEY,
  type       VARCHAR(100) NOT NULL,
  payload    JSON,
  created_at DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

| Column    | Type         | Description                                         |
| --------- | ------------ | --------------------------------------------------- |
| `type`    | VARCHAR(100) | `disk`, `ram`, `ollama`, `alert`                    |
| `payload` | JSON         | Event data (e.g. `{ "drive": "C", "usedPct": 62 }`) |

Append-only — no UPDATE, no DELETE. The background worker writes every 60 s. `GET /api/events/recent` returns the last 50 entries.

### `profiles` — User Profiles (v3.1.0)

```sql
CREATE TABLE IF NOT EXISTS profiles (
  id         INT AUTO_INCREMENT PRIMARY KEY,
  name       VARCHAR(255) NOT NULL,
  color      VARCHAR(7)   NOT NULL DEFAULT '#7C3AED',
  pin_hash   VARCHAR(255),
  pin_salt   VARCHAR(255),
  is_default BOOLEAN      NOT NULL DEFAULT FALSE,
  created_at DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);
```

| Column       | Type         | Description                                           |
| ------------ | ------------ | ----------------------------------------------------- |
| `pin_hash`   | VARCHAR(255) | PBKDF2 hash (100k iterations, SHA-512), NULL = no PIN |
| `pin_salt`   | VARCHAR(255) | Random salt, 32 bytes as hex                          |
| `is_default` | BOOLEAN      | Exactly one profile is default (loaded on startup)    |

`memories` and `sessions` have a `profile_id INT NULL` column — NULL means the default profile.

CREATE TABLE IF NOT EXISTS tasks (

| Column       | Type | Description                                                      |
| ------------ | ---- | ---------------------------------------------------------------- |
| `priority`   | ENUM | `high` → `normal` → `low` — sort order in `list_tasks`           |
| `due_date`   | DATE | Optional due date — taken into account in the end-of-day summary |

## Useful Admin Commands

```sql
-- Active connections
SHOW PROCESSLIST;

-- Table sizes
SELECT table_name,
       ROUND(data_length / 1024, 2) AS data_kb,
       ROUND(index_length / 1024, 2) AS index_kb
FROM information_schema.tables
WHERE table_schema = 'ella';

-- Tool executions in the last hour
SELECT tool_name, success, error, executed_at
FROM tool_executions
WHERE executed_at > NOW() - INTERVAL 1 HOUR
ORDER BY executed_at DESC;

-- Active allow rules
SELECT id, name, tool_name, `trigger`, action
FROM rules
WHERE enabled = 1
ORDER BY action DESC, id;

-- Recent memories
SELECT id, type, content, created_at
FROM memories
ORDER BY created_at DESC
LIMIT 20;

-- Sessions with message count
SELECT s.id, COUNT(m.id) AS messages, s.updated_at
FROM sessions s
LEFT JOIN session_messages m ON m.session_id = s.id
GROUP BY s.id
ORDER BY s.updated_at DESC;
```
